Mode d’emploi et limites du rendu
  • Choisir un aperçu puis un scénario. Les boutons ci-dessus ne font pas partie du produit. Les commandes de scénario remplacent volontairement les données de démonstration.
  • Cliquer + / ✓ dans la bibliothèque : un clic = une ressource et un jeton, sans modifier le brouillon. La bibliothèque reste ouverte. Le − du compositeur retire uniquement ce projet.
  • Les ressources sélectionnées persistent après l’envoi et limitent strictement les preuves admissibles. Sans sélection : base publique déployée seulement, jamais le Web ou des données privées. Aucun bandeau historique vide ou libellé global.
  • Les jetons actifs restent au-dessus de la saisie dans une seule rangée défilante (glisser, molette horizontale, flèches au focus ou tabulation vers les retraits). La petite flèche est une aide illustrative, pas un token visuel approuvé. Les jetons historiques se répartissent sur plusieurs lignes, sans contrôle de retrait.
  • Envoyer crée un instantané immuable. Pendant l’attente, modifier le brouillon et les projets du prochain tour ; l’envoi est désactivé. Utiliser « Recevoir… » ou « Simuler une erreur » : arrivée d’un bloc, sans streaming ni délai réel, sans effacer le prochain brouillon ou sa sélection. Aucun envoi en file d’attente.
  • Sur une grande largeur, la bibliothèque occupe la marge droite sans déplacer le chat. Sinon, même sur desktop, elle se superpose en feuille basse au-dessus du compositeur. Fermer ou appuyer sur Échap restitue le focus, sans scroll imposé. Pour tester la lecture haute, envoyer plusieurs questions puis remonter avant une réponse simulée.
  • Confidentialité = scaffold sans disclosures. Citations et extraits ne sont pas simulés ici : les jetons de périmètre ne sont pas des citations. Pas d’upload, de vraie KB, d’évaluation du candidat, de réseau applicatif ni de persistance/recovery runtime. Seule la feuille de polices distante héritée de v2 peut être sollicitée. Clavier virtuel et dimensions finales hors validation de ce rendu.
