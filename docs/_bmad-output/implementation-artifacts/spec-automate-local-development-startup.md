## Intent

**Problem:** Daily WSL development currently requires repeating a long Bash/fnm initialization block in each terminal. The silent WORKSTATION_READY guard is confusing when initialization is omitted.

**Approach:** After committing the existing workstation evidence as requested, add a repository-local Bash launcher that selects the pinned Node with the installed fnm, runs the existing workstation gate and starts both local services by default. Support worker-only and frontend-only modes. One Ctrl+C must stop all services owned by that invocation; a failed service must stop its sibling and produce a nonzero result. Keep existing protected npm commands, tool pins, lockfile, shell profiles/defaults, unrelated processes, local data and secrets unchanged. Do not automatically install tools/packages, initialize/reset databases or deploy. Update daily-startup documentation while preserving dated evidence and the tested manual fresh-clone instructions.
