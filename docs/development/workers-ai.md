# Workers AI: offline preparation only

The shipped Worker has **no inference binding or configured message processor**. `selectProvider()` needs no credentials and supplies the existing local bootstrap simulation; its ping is not a chat answer. Health checks only the publication. No environment variable enables inference. Do not use these fixtures to try the target account.

## What can be exercised without an account

Use `selectProvider({ mode: 'workers-ai-offline', binding, classifier, generator, isProxy })` **only with the local fixture port**. Both role configurations explicitly require a listed model and component/output budgets. An incomplete configuration rejects; it does not switch providers. The role receiver accounts the exact serialized binding input (two messages, role-specific JSON schema, `stream: false`, reserved `max_tokens`); the prepared call is bound to its receiver. The Unicode-scalar counter and output cap are **test accounting only**, not a live tokenizer or billing guard. The port accepts a non-streaming `output.response` containing either a JSON object or its JSON text. Text is bounded before parsing. Both forms then pass a descriptor-based JSON tree check and serialized output accounting before core validation. The offline host supplies a trusted native proxy check (`node:util/types`’s `isProxy` in tests); the adapter does not invoke getters or serialization hooks on binding objects. Unexpected shapes, cyclic graphs and malformed or oversized output are rejected, not coerced. The caller's cancellation signal is forwarded; abandoning the call locally does not prove remote computation stopped.

Construct the offline provider **once before** registering `createWorker`: `const model = selectProvider(config)` validates both static role configurations synchronously. Only then pass a factory closing over `model` to `createWorker`; defer only request-dependent catalog/retrieval wiring, not role validation, until after admission. A `503 provider_unavailable` is a rejection before admission, not a saved failed turn: preserve the draft and deliberately submit it after restoration, not via retry-of-failure.

For object responses the fixture producer must supply an already size-bounded, plain JSON object: enumerating its keys can allocate before the adapter checks the output reservation. The reservation bounds accepted output, **not** transport allocation or heap use. Require an upstream byte bound before any real object transport. An ignored/missing cancellation signal does not guarantee settlement; enforce a real attempt deadline before activation.

The optional `createWorker` processor factory receives the public catalog and scoped retriever; a local composition can use `ProfessionalIntentProcessor`, `ModelAwareIntentPreparation` and `EligibleEvidenceContinuation` with the two model ports. Core, not the provider, chooses history and eligible evidence, validates output, reconstructs citations, and owns admission, failure, retention and replay. A trusted availability snapshot is scoped to **required calls of that composition**, not supplied by a visitor or polled from a model. It may suspend new work on confirmed unavailability and include a separately established resume timestamp. Do not turn an unknown error or a generator-only failure into a classifier-wide suspension. No automatic outage cache or execution budget. An admitted rejection can save one controlled failure; an unconfirmed commit is still unknown. Authenticated saved results remain readable without inference.

Offline evidence: `tests/bootstrap/workers-ai.test.ts` exercises binding inputs, reservation, error pairs and cancellation. `tests/bootstrap/conversation-results.test.ts` captures both roles through real processing and authenticated admission with in-memory synthetic stores; it checks data separation, saved failures, replay and uncertainty. Neither suite requires a network port or operator storage. Full regression/smoke verification requires a disposable source fixture with isolated PID/network namespaces, clean settings and free ports; do not run the process-inspecting harness on an operator host.
